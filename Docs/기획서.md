## 1. 게임 개요

플레이어는 용병 **한 명**을 육성한다 [확정].
- **육성 단계**: 일과(훈련, 휴식 등)를 정한다.
- **전투**: 적과 1대1로 맞붙어 매 턴 행동을 고른다.
- **사망**: 실전에서 패배하면 용병은 죽는다. 그 용병의 기록이 남고, 새 용병으로 다시 시작한다 [확정].

### 핵심 루프

```
           ┌──────────────────────────────────────────────────────────┐
           ▼                                                          │
[캐릭터 생성] ──▶ 육성 단계(일과 지정) ──▶ 전투(1대1)                 │
                     ▲                      ├─ 승리 ─▶ 기력 소모 ─────┘(육성 단계로)
                     │                      ├─ 연습전 패배 ─▶ 육성 단계로
                     └──────────────────────┘
                                            └─ 실전 패배 ─▶ 사망 ─▶ 기록 저장 ─▶ [캐릭터 생성]
```

## 2. 용병

### 2.1 기본 원칙 [확정]
- 플레이어가 관리하는 용병은 **한 명**이다. 목록·선택 개념이 없다.

### 2.2 능력치
| 능력치 | 범위 | 용도 |
|---|---|---|
| 힘 | 1–10 | 무기 공격력(둔기·창) |
| 민첩 | 1–10 | 무기 공격력(검·창), 행동 순서 |
| 건강 | 1–10 | 최대 HP(건강 × 10) [제안] |
| 지능 | 1–10 | **마법사 계열에 보너스** [확정] — 세부 내용은 [미정: CHAR-2] |
| 매력 | 1–10 | **대화 이벤트에서 유리한 선택지 확보** [확정] |

- 생성 시 가중 랜덤 롤(7 이상 희소)은 유지한다 [제안].
- **기력**(0–100): 육성 단계의 일과와 **전투 승리**로 소모한다. 전투 중에는 쓰지 않는다 [확정].
- **HP**: 전투가 끝나도 회복되지 않고 **다음 전투까지 이어진다** [확정]. 회복 수단은 [미정: HP-1], 최대 HP가 늘 때 현재 HP 처리는 [미정: HP-4].
- **사기**: 삭제 [확정].

## 3. 자원 [확정: 유지]

용병 한 명 체제에서도 **골드 · 보급 · 영향력**을 유지한다.

| 자원 | 용도(초안) [제안] |
|---|---|
| 골드 | 장비 구입, 훈련 비용. 실전 승리 보상 |
| 보급 | 휴식·회복 일과의 비용 |
| 영향력 | 대화 이벤트와 상위 의뢰 해금 |

## 4. 육성 단계 (관리 턴)

### 4.1 구조 [제안]
1. **계획** — 플레이어가 용병의 일과를 하나 고른다.
2. **실행** — 일과 효과를 적용한다. 능력치, 숙련도, 기력, 자원이 바뀐다.
3. **정산** — 턴 결과를 보여주고 다시 계획 단계로 돌아간다.

- 일과는 플레이어가 **직접 고른다**. 고른 일과는 **턴을 넘겨야만 실행**되며, 넘기기 전에는 얼마든지 바꿀 수 있다 [확정].
- 일과를 고르지 않으면 턴을 넘길 수 없다. 자율 행동(기본 휴식)은 없다 [확정].
- 매 턴 결과 팝업과 요약 로그를 남긴다. 팝업은 설정에서 끌 수 있다 [확정] — 상세는 [UI_육성화면.md](UI_육성화면.md).

### 4.2 일과 [제안]
| 일과 | 효과(초안) |
|---|---|
| 훈련 | 기력 −15. 고른 숙련의 경험치 획득. 일정 확률로 **스킬 습득** (습득 방식은 [미정: SKILL-1]) |
| 휴식 | 기력 +30, 보급 소모 |
| 연습전 | 연습 전투 1회. 패배해도 사망하지 않음 |
| 출전 | 실전 1회. 패배하면 사망 |

- 일과는 `ActionDefinition` 애셋과 `ActionCatalog`로 정의한다.
- 기력이 부족하면 출전할 수 없다. 휴식으로 회복해야 한다 [제안]. 기력·HP 부족 시 제약 범위는 [미정: STA-2, HP-3].

### 4.3 화면 구성
- 육성 화면 UI는 [UI_육성화면.md](UI_육성화면.md)에 정리한다.

## 5. 전투 (1대1 턴제)

### 5.1 기본 원칙 [확정]
- 전투는 **용병 1명 vs 적 1명**으로 진행한다.
- 매 턴 플레이어는 **공격 / 방어 / 대기 / 스킬** 중 하나를 고른다.
- 양측은 **동시에** 행동을 고르고, **상대의 선택을 알 수 없다**.
- 전투 중에는 **기력을 쓰지 않는다**.
- 전투는 용병의 **현재 HP**로 시작하고, 끝난 뒤의 HP가 그대로 남는다 [확정].
- 전투 전에는 **상대 정보를 아무것도 공개하지 않는다** (이름·무기·능력치 모두) [확정].

### 5.2 전투 종류 [확정]
| 종류 | 패배 시 | 승리 시 |
|---|---|---|
| **실전** | 용병 **사망** → 기록 저장 → 캐릭터 생성 화면 | 기력 소모, 보상 |
| **연습전** | 사망하지 않고 육성 단계로 복귀 | 기력 소모 |

- 연습전도 승리하면 기력을 소모한다 [확정: 승리 시 기력 소모]. 소모량은 [미정: STA-1].
- 연습전 보상과 숙련도 획득 여부, 상대는 [미정: BATTLE-1]. 연습전 패배 후 HP는 [미정: HP-2].
- 실전 상대 구성·난이도·보상 규모는 [미정: BATTLE-3].

### 5.3 라운드 진행

```
① 선택 단계 : 플레이어와 적 AI가 동시에, 서로 모르는 상태에서 행동을 고른다. [확정]
② 해결 단계 : 방어를 가장 먼저 적용하고, 나머지는 행동속도가 빠른 쪽부터 처리한다. [제안]
③ 종료 단계 : 스킬 쿨다운 감소, 상태이상 처리, 승패 판정 [제안]
```

- **행동속도** = 민첩 × 운용 속도 배율. 기존 `CombatMath.SpeedMultiplier`를 재사용한다 [제안].
- **승패**: 상대 HP를 0으로 만들면 승리, 내 HP가 0이 되면 패배.

### 5.4 기본 행동 [확정]

| 행동 | 효과 |
|---|---|
| **공격** | 장착 무기로 일반 공격 |
| **방어** | 이번 라운드에 받는 피해 감소 |
| **대기** | 아무 행동도 하지 않고 턴 종료 |

- 실전 중 도주 가능 여부는 [미정: BATTLE-2].

**수치 초안 [제안]**
- 방어 시 받는 피해 −50%. 방패 운용이면 방패술 감소율을 추가로 적용한다.
- 공격 피해 = `유효 공격력 × 상성 배율 × (1 − 피해 감소)` (기존 공식 유지)
- 명중률 = `기본 90% + 숙련·운용 명중 − 상대 회피` (기존 공식 유지)

### 5.5 스킬

**사용 흐름 [확정]**
```
[스킬] 버튼 ──▶ 장착 스킬 목록 표시 ──▶ 스킬 선택 ──▶ 이번 라운드 행동으로 확정
                       └─ 쿨다운 중인 스킬은 회색으로 표시
```

**획득 [확정]**
- **숙련 레벨 해금**: 숙련 레벨이 조건에 도달하면 자동으로 얻는다.
- **훈련**: 육성 단계의 훈련 일과로 얻는다. 얻는 방식은 [미정: SKILL-1].

**규칙 [제안]**
- 장착 슬롯은 **3칸**이다. 장착과 교체는 전투 밖(육성 단계)에서만 한다.
- 전투 중 기력을 쓰지 않으므로 스킬 사용은 **쿨다운(턴)**으로만 제한한다.
- 무기 고유 **필살기**(숙련 Lv5 해금)는 **전투당 1회**만 쓸 수 있다.
- 스킬은 `SkillDefinition` ScriptableObject로 정의한다. 행동·무기와 같은 패턴이다.

**스킬 예시 [제안]**
| 스킬 | 계열 | 획득 | 효과 | 쿨다운 |
|---|---|---|---|---|
| 연속 베기 | 검술 | 검술 Lv2 | 2회 타격, 회당 피해 60% | 2턴 |
| 찌르기 견제 | 창술 | 창술 Lv2 | 피해 80%, 이번 라운드 선공 보장 | 2턴 |
| 내려찍기 | 둔기술 | 둔기술 Lv2 | 피해 120%, 상대 방어 효과 절반 무시 | 3턴 |
| 방패 밀치기 | 방패술 | 훈련 | 피해 50%, 30% 확률로 상대 1턴 기절 | 3턴 |
| (필살기) | 무기별 | 숙련 Lv5 | 무기별 고유 효과 | 전투당 1회 |

### 5.6 적 [제안]
- 적도 플레이어와 같은 행동 체계(공격·방어·대기·스킬)를 쓴다.
- 적 정의(`EnemyUnitDefinition`)에 **장착 스킬**과 **행동 성향**을 추가한다. 성향은 공격형·수비형처럼 행동별 가중치로 표현한다.
- 기본 AI 초안: HP가 낮을수록 방어 확률을 올리고, 쿨다운이 끝난 스킬은 일정 확률로 쓴다.

## 6. 숙련도

### 6.1 성장 경로 [확정]
- **전투**: 특정 행동이나 스킬을 쓰면, 사용한 행동에 해당하는 숙련도를 얻는다.
- **육성 단계**: 일과(훈련 등)를 수행하면 숙련도가 쌓인다.

### 6.2 숙련도의 두 계층 [확정]

| 계층 | 대상 | 개수 |
|---|---|---|
| **계열 숙련** | 검술 · 창술 · 둔기술 · 방패술 | 4종 고정 |
| **스킬 숙련** | 보유한 스킬 각각 | 스킬마다 하나씩 |

- 모든 스킬은 하나의 **계열 숙련**에 속한다. 해금 조건이 "검술 Lv5"인 스킬은 검술 계열 스킬이다.
- **스킬을 쓰면 계열 숙련과 그 스킬의 숙련이 함께 오른다.**
- **계열 숙련을 올려도 스킬 숙련은 오르지 않는다.** 스킬 숙련은 그 스킬을 직접 써야만 오른다.

```
        [스킬 A 사용] ──┬──▶ 스킬 A 숙련 ↑
                        └──▶ 검술 ↑
   [일반 공격 / 훈련] ─────▶ 검술 ↑      (스킬 A 숙련은 그대로)
```

### 6.3 행동별 획득 숙련
| 사용한 것 | 계열 숙련 | 스킬 숙련 |
|---|---|---|
| 공격 | 장착 무기의 지배 숙련(검술·창술·둔기술) [확정] | — |
| 방어 | 방패 운용이면 방패술 [제안]. 아니면 [미정: PROF-1] | — |
| 대기 | 없음 [확정] | — |
| 스킬 | 그 스킬의 계열 숙련 [확정] | 사용한 스킬 [확정] |
| 훈련 일과 | 훈련 대상으로 고른 계열 숙련 [제안] | [미정: PROF-3] |

### 6.4 레벨과 효과
- **계열 숙련**: 기존 Lv1~5 곡선을 유지한다(`ProficiencyCurve`) [제안].
  - 레벨마다 명중·피해 보정이 오른다.
  - Lv3에서 양손 운용, Lv5에서 필살기가 해금된다.
  - 스킬의 해금 조건으로 쓰인다.
- **스킬 숙련**: 레벨이 오르면 그 스킬이 강해진다 [제안]. 예: 피해 배율 증가, 쿨다운 감소, 부가 효과 확률 증가. 레벨 상한과 단계별 효과는 [미정: PROF-2].
- 레벨마다 필요한 경험치와 행동당 획득량은 별도 SO에 둔다 [제안].

## 7. 사망과 캐릭터 생성 [확정]

- 실전에서 패배하면 용병은 **사망**한다.
- 사망한 용병의 정보를 **저장**한 뒤 **신규 캐릭터 생성 화면**으로 넘어간다.

**사망 기록 [확정]**
- 기록은 **열람 전용**이다. 게임 진행에는 아무 영향을 주지 않는다.
- 다음 캐릭터에 **계승되는 요소는 없다**. 자원(골드·보급·영향력)도 새 캐릭터에서 초기값으로 다시 시작한다.

**저장할 정보 [제안]**: 이름, 최종 능력치, 계열 숙련, 보유 스킬과 스킬 숙련, 생존 턴 수, 전적(승/패), 사망 원인(마지막 상대)

**기록 열람 [제안]**: 타이틀 화면이나 캐릭터 생성 화면에서 역대 용병 목록을 열고, 한 명을 골라 상세 기록을 본다.

**신규 캐릭터 생성 [제안]**: 능력치 랜덤 롤과 시작 무기 1종 특화(기존 `WeaponRoll` 방식)를 바탕으로, 이름을 입력하고 확정한다. 재굴림·포인트 분배·무기 선택 여부는 [미정: CHAR-1].

- 살아 있는 용병의 진행 상황은 자동 저장되고, 메인 화면에서 이어서 할 수 있다 [확정] — 11.2. 사망하면 진행 세이브는 지운다 [제안].

## 9. 무기 시스템 (1대1에 맞춘 재해석) [제안]

무기 3종, 숙련 4종, 운용 3종, 상성 고리(창 > 검 > 둔기 > 창)는 **유지**한다. 포메이션과 전투 중 기력에 의존하던 특성만 바꾼다.

| 기존 특성 | v2 재해석 |
|---|---|
| 창: 사거리 2, 후열 직접 타격 | **선공 견제** — 행동속도 보너스 |
| 검: 후열 침투 | **회피·연타** — 회피 보너스, 연타형 스킬 |
| 둔기: 전열 붕괴 | **방어 관통** — 상대 방어 효과 일부 무시 |
| 양손검: 1열 전체 광역 | **다단 히트** — 일반 공격이 2회 타격(회당 피해 감소) |
| 양손창: 사거리 3, 2체 관통 | **강선공** — 첫 라운드 무조건 선공 + 피해 보너스 |
| 양손둔기: 방어 무시 + 넉백 | **방어 무시 + 기절** — 상대 방어를 완전히 무시하고 확률적으로 1턴 기절 |
| 한손 단독: 이동력 +1 | 이동 개념이 없으므로 **삭제** |
| 운용별 전투 기력 소모 배율 | 전투 중 기력을 쓰지 않으므로 **승리 후 기력 소모량 배율**로 전환(한손 단독 −20%, 양손 ×1.5) |

- 마법사 계열(마법 무기·숙련·스킬)의 추가 범위와 시기는 [미정: MAGIC-1].

## 10. 구현 원칙

기획 전환(v2) 이후에도 유지하는 구조다. 구현이 남은 작업은 [미구현_목록.md](미구현_목록.md)에 시스템별로 정리한다.

- `GameEvents` 이벤트 버스를 쓰고, 시스템끼리 직접 참조하지 않는다.
- 무기 규칙 계층(`CombatMath`, `WeaponMatchup`, `ProficiencyCurve`, `CombatBalanceConfig`, `WeaponDefinition`, `WeaponLoadout`, `WeaponRoll`)은 순수 규칙으로 유지한다.
- 일과·무기·스킬·적처럼 종류가 늘어나는 데이터는 ScriptableObject 정의 + 카탈로그 패턴으로 만든다.
- 키 입력은 `KeyboardInputManager`에 모으고, 각 패널은 요청 이벤트만 받는다.
- 순수 규칙·포매터는 EditMode 테스트 대상으로 둔다.

## 11. 메인 화면과 진행 저장

### 11.1 메인 화면
게임을 실행하면 메인 화면(`MainMenu` 씬)이 먼저 열린다. 메뉴 네 가지는 [확정], 세부 동작은 [제안]이다.

| 메뉴 | 동작 |
|---|---|
| 새로 시작 | 새 용병으로 육성을 시작한다. 진행 중인 세이브가 있으면 "저장된 진행이 사라진다"고 확인을 받는다. 캐릭터 생성 화면(7장)이 생기기 전까지는 임시 용병으로 바로 시작한다 |
| 이어서 시작 | 저장된 진행을 불러온다. 버튼 오른쪽에 용병 이름과 턴(`카일 · 12턴`)을 보여준다. 세이브가 없거나 읽을 수 없으면 흐리게 비활성으로 두고 "저장된 진행 없음"을 표시한다 |
| 설정 | 설정 창을 연다: 화면 모드(창/전체 화면), 해상도, 턴 결과 팝업 생략. 육성 화면 `[≡]` 메뉴의 설정 창([UI_육성화면.md](UI_육성화면.md) 3.6)과 같은 창이다 |
| 종료 | 확인 창을 거쳐 게임을 끈다 |

- 레이아웃: 왼쪽 띠 영역에 제목과 세로 버튼 4개, 오른쪽 아래에 버전 표시. 설정·확인 창은 화면을 어둡게 덮는 팝업이고 Esc로 닫는다.
- 사망 기록 열람(7장)은 기록 저장이 구현되면 메뉴에 추가한다.

### 11.2 진행 저장 [확정]
- 살아 있는 용병의 진행 상황을 저장하고 이어서 할 수 있다 (2026-11-16 확정).
- 슬롯은 하나다. 용병이 한 명뿐이고 사망하면 새로 시작하는 구조이기 때문이다 [제안].
- **자동 저장** [제안]: 매 턴 계획 단계가 시작될 때 저장한다. 저장 버튼은 따로 없다. 실행 도중에 게임을 끄면 그 턴의 계획 단계부터 다시 한다.
- 지금 저장하는 것: 턴 수, 용병의 능력치·기력·현재 HP·해금된 일과·무기·운용·계열 숙련 레벨. 고른 일과는 저장하지 않는다(매 턴 새로 고른다).
- 자원·숙련 경험치·스킬·전적처럼 아직 없는 데이터는 해당 시스템을 만들 때 세이브에 추가한다.
- 사망하면 진행 세이브를 지운다 [제안]. 사망 기록(7장)은 별도로 남는다.
- 설정은 세이브가 아니라 기기 설정(`PlayerPrefs`)으로 저장한다. 새로 시작해도 유지된다.
